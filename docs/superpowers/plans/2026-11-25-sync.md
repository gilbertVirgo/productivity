# Stint Sync Implementation Plan (plan 4 of 8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Mac's local SwiftData store syncs two ways with Supabase. Sync covers:
- the user signs in;
- local writes are pushed;
- remote changes are pulled on launch and via Realtime;
- server-written goal points and goal results arrive locally;
- the Mac carries out `session_command` rows that the phone will send in plan 5.

**Architecture:**
- **New package target.** The SwiftData models and `Ledger` move out of the Mac target into a new `StintData` target in the `Shared` package, so the iPhone app (plan 5) can reuse them.
- **`Sync/` folder.** `StintData` gains a `Sync/` folder:
  - Codable row types that mirror the Postgres tables;
  - pure merge and dirty rules;
  - a `SyncEngine` that pushes and pulls through `supabase-swift`.
- **No outbox table.** A row is dirty when `syncedAt == nil || updatedAt > syncedAt`. Every local edit already stamps `updatedAt`. Deletes leave a `Tombstone`.
- **Append-only rows** have stable ids and are pushed with ignore-duplicates. These are session events, session allow rows and point events. Event ids are derived deterministically from the session id and the array index.

**Tech Stack:** supabase-swift 2.x (`from: "2.55.0"`), SwiftData, Swift 6, Swift Testing, local Supabase (plan 2 migrations), XcodeGen.

**Spec:** `docs/superpowers/specs/2026-11-24-freelance-focus-app-design.md`, §5 (data model), §6.11 (sync) and §6.3 (session_command, 10 s acknowledgement).

## Global Constraints

- **Column names and enum strings are the plan 2 schema's.** Read `supabase/migrations/20261125000001_schema.sql`; that file is the authority. Field mapping:
  - `colorHex` ↔ `color`
  - `refID` ↔ `ref_id`
  - `AllowRule` ↔ `project_allow`
  - `TaskItem` ↔ `task`
  - `SessionRecord` ↔ `session` (always `device = "mac"`)
  - `Treat` ↔ `treat`
  - `PointEvent` ↔ `point_event`
- **Last-write-wins on `updated_at`.** A remote row overwrites local only when `remote.updated_at > local.updatedAt`. The server also rejects stale updates (trigger `reject_stale_update`).
- **Append-only tables** (`session_event`, `session_allow`, `point_event`): insert with `Prefer: resolution=ignore-duplicates` (supabase-swift: `.upsert(rows, onConflict: "id", ignoreDuplicates: true)`). Never update them.
- **Stable ids for derived rows.** The rule is `SyncIDs.derived(sessionID, kind, index)`: UUIDv5-style, SHA-1 over `sessionID.uuidString + "/" + kind + "/" + index`, with version and variant bits set. The kinds are:
  - `"event"`: index into `eventsData`;
  - `"snap"`: index into `allowData`;
  - `"add"`: index into `allowAddedData`.
- **`project.created_at` is never sent.** The server default stamps it on first insert. This prevents `close_periods` from closing pre-sync days as missed (plan 2 final review backfill race).
- **`profile`** is upserted with `onConflict: "user_id"`. It carries:
  - `timezone = TimeZone.current.identifier`;
  - `break_allowance_min` from UserDefaults `breakAllowanceMin` (default 60);
  - `display_name` from UserDefaults `displayName` (default "").
- **Dates** use ISO-8601 with fractional seconds both ways (`SyncCoding.encoder/decoder`).
- **Sync never blocks the UI or breaks local use.** Signed out means local-only, exactly as today. Sync errors are logged with `os.Logger(subsystem: "dev.stint.mac", category: "sync")` and retried on the next pass.
- **Config.** Supabase URL and anon key come from Info.plist keys `StintSupabaseURL` and `StintSupabaseAnonKey`. They are set via `project.yml` build settings `STINT_SUPABASE_URL` and `STINT_SUPABASE_ANON_KEY`. The defaults are the local stack's: `http://127.0.0.1:54321` and the local anon key printed by `supabase status`. The local anon key is a public default, so it is safe to commit. `NSAppTransportSecurity › NSAllowsLocalNetworking = YES`.
- **Testing:**
  - SwiftPM tests: `cd Shared && swift test --disable-sandbox`.
  - App: `xcodegen generate && xcodebuild -project Stint.xcodeproj -scheme StintMac -destination 'platform=macOS' -derivedDataPath DerivedData test`.
  - DB: `supabase db reset && supabase test db`.
- Work on `main`. Commit trailer: `Co-Authored-By: <model you run as> <noreply@anthropic.com>`.

## Decisions taken in this plan (rulings)

- **Auth in this plan is the email one-time code** (`signInWithOTP` + `verifyOTP`). Locally, the code shows up in Inbucket at http://127.0.0.1:54324.
  - Sign in with Apple needs the `com.apple.developer.applesignin` entitlement. That entitlement needs a Development Team, and an ad-hoc-signed app carrying it is killed at launch.
  - So Sign in with Apple is added in plan 5, once the user has signed into Xcode with their developer account.
- **No outbox model.** A dirty flag (`syncedAt`) is enough because every edit path already stamps `updatedAt`. The plan 3 reviews checked this. The only hard delete, removing an allow rule, writes a `Tombstone`.
- **The session row is pushed whenever it is dirty.** Checkpoints restamp `updatedAt`, so that is every ~15 s while running, plus start and close.
  - Its events and allow rows are pushed with it each time; ignore-duplicates makes repeats free.
  - This gives the phone near-live state without a separate channel.
- **Realtime is only a trigger.** Any change event on the user's tables schedules a debounced pull (1 s). Rows are never applied straight from the socket payload. The pull is the one code path that writes remote data.
- **Session commands older than 10 s are deleted unhandled.** The phone has already shown "Mac not reachable" for them (§6.3).
- **`goal_result` is pulled into a local `GoalResultRecord`.** The Mac UI doesn't show it yet; plans 5 and 8 will.

### Task 2: Row types, mapping, stable ids, merge rules (pure)

**Files:**
- Create: `Shared/Sources/StintData/Sync/{SyncCoding,SyncIDs,Rows,Mapping,SessionCommand}.swift`
- Test: `Shared/Tests/StintDataTests/{SyncIDsTests,MappingTests,SessionCommandTests}.swift`

**Interfaces:**
- Consumes: Task 1 models; Core `SessionEvent`, `AllowEntry`.
- Produces (all public):
  - `enum SyncCoding { static let encoder: JSONEncoder; static let decoder: JSONDecoder }`. These use ISO-8601 with fractional seconds. The decoder also accepts no fractional seconds and Postgres's `+00:00` offset.
  - `enum SyncIDs { static func derived(_ sessionID: UUID, _ kind: String, _ index: Int) -> UUID }`. It uses SHA-1 via `CryptoKit.Insecure.SHA1` over the UTF-8 of `"\(sessionID.uuidString)/\(kind)/\(index)"`. It takes the first 16 bytes, then sets `byte6 = (b6 & 0x0F) | 0x50` and `byte8 = (b8 & 0x3F) | 0x80`.
  - Row structs, `Codable, Sendable, Equatable`, using snake_case `CodingKeys` that exactly match the schema columns. All of them except `ProfileRow` carry `id: UUID` and `userID: UUID` (key `user_id`):
    - `ProjectRow`: updated_at, name, share_alias, color, weekly_hours_goal, daily_hours_goal, daily_goal_days, tasks_goal, tasks_goal_period, shared, archived_at. No created_at.
    - `ProjectAllowRow`: updated_at, project_id, kind, value, label.
    - `TaskRow`: updated_at, project_id, title, estimate_min, estimate_guessed, done_at, source, sort.
    - `SessionRow`: created_at, updated_at, project_id, first_task_id, planned_min, started_at, ended_at, end_kind, early_reason, device.
    - `SessionAllowRow`: session_id, kind, value, label, added_mid_session, reason.
    - `SessionEventRow`: session_id, at, type, detail (`[String: String]`, default `[:]`).
    - `PointEventRow`: at, delta, kind, ref_id, note.
    - `TreatRow`: updated_at, name, cost, archived_at.
    - `GoalResultRow`, decode only: project_id, period, period_start (a `"yyyy-MM-dd"` string), goal_kind, target, actual, met, created_at.
    - `ProfileRow`: user_id, updated_at, timezone, break_allowance_min, display_name.
    - `SessionCommandRow`: id, user_id, created_at, kind, payload (`[String: String]`).
  - `enum Mapping`:
    - `row(_ p: Project, userID:) -> ProjectRow`, and the same for `AllowRule` (needs `projectID` from `rule.project?.id`; a rule without a project is skipped by returning nil), `TaskItem`, `Treat`, `SessionRecord`, `PointEvent`.
    - `sessionChildren(_ s: SessionRecord, userID:) -> (allow: [SessionAllowRow], events: [SessionEventRow])`. Snapshot entries come from `allowData` with `added_mid_session = false` and no reason. Added entries come from `allowAddedData` with `reason = allowReasons[i]` when present. Events come from `eventsData`, with `detail ?? [:]`. Ids use `SyncIDs.derived`.
    - `apply(_ row: ProjectRow, to: Project) -> Bool`: applies the row and returns true only if `row.updatedAt > local.updatedAt`. When it applies, it sets `syncedAt = row.updatedAt`. There are matching `apply` functions for task, allow rule, treat and session. For a session, never apply over a local row whose `endedAt == nil`, because the Mac owns the running session.
    - `insert(_ row: …, in ctx:) -> Model`: creates a local model from a row that has no local counterpart, with `syncedAt = row.updatedAt`. It covers project, allow rule (attached to its project, looked up by id), task (same), treat, point event and goal result. Do not insert sessions from remote rows; only the Mac creates sessions. Pulled `point_event` rows set `createdAt = updatedAt = at`.
  - `enum SessionCommand: Equatable { case start(projectID: UUID, plannedMin: Int, firstTaskID: UUID?), takeBreak, resume, endEarly(reason: String) }`, with `static func parse(_ row: SessionCommandRow) -> SessionCommand?`.
    - Payload keys: `project_id`, `planned_min`, `first_task_id`, `reason`.
    - `kind`: `start`, `break`, `resume`, `end_early_request`.
    - Return nil when a required field is missing or malformed, or when `end_early_request` has a reason that is empty after trimming.

### Task 3: Realtime publication + `SyncEngine` (push/pull) + integration test

**Files:**
- Create: `supabase/migrations/20261125000004_realtime.sql`, `supabase/tests/03_realtime_test.sql`, `Shared/Sources/StintData/Sync/SyncEngine.swift`, `Shared/Tests/StintDataTests/SyncIntegrationTests.swift`

**Interfaces:**
- Consumes: Task 2 rows, mapping and coding; supabase-swift `SupabaseClient`.
- Produces:
  - `@MainActor public final class SyncEngine` with `init(client: SupabaseClient, context: ModelContext)`.
  - `public func push(userID: UUID) async throws` sends, in order:
    1. profile (upsert `onConflict: "user_id"`). Its `updated_at` is UserDefaults `profileUpdatedAt`. If that key is unset, write `Date.now` into it first. The server trigger silently skips any update older than the stored row, so a stale profile is a no-op, not an error;
    2. dirty projects;
    3. dirty allow rules;
    4. dirty tasks;
    5. dirty treats;
    6. dirty sessions;
    7. their `sessionChildren` (ignore-duplicates);
    8. dirty point events (ignore-duplicates);
    9. tombstones, as a `delete().eq("id", rowID)` on that table; on success, delete the Tombstone.

    After each successful batch it sets `syncedAt = updatedAt` on the pushed models and saves. Editable tables use a plain upsert (`onConflict: "id"`).
  - `public func pull() async throws` handles each editable table (project, project_allow, task, treat, session):
    - It selects rows with `updated_at > watermark`. Watermarks live in UserDefaults under `sync.watermark.<table>`, and the first pull uses the epoch.
    - For each row it calls `apply` or `insert`, then advances the watermark to the max `updated_at` seen.
    - Append-only `point_event` and `goal_result` are selected by `created_at > watermark` and only inserted when the id is missing locally.
    - It saves once at the end.
  - `public func startRealtime(onChange: @escaping @MainActor () -> Void) async` subscribes to `postgres_changes` on schema `public`, for the editable tables plus `point_event`, `goal_result` and `session_command`. It calls `onChange` per event.
  - `public func stopRealtime() async`.
  - `public func pendingCommands() async throws -> [SessionCommandRow]` and `public func deleteCommand(_ id: UUID) async throws`.

**Files:**

- Test: `MacTests/SyncCoordinatorTests.swift` (command dispatch only)

**Interfaces:**
- Consumes: `SyncEngine`, `SessionCommand.parse`, AppState's `start/takeBreak/resume/endEarly(reason:)`.
- Produces: `@MainActor @Observable final class SyncCoordinator`.
  - Properties: `state: enum { signedOut, signingIn, signedIn(email: String) }`, `lastSync: Date?`, `lastError: String?`.
  - Methods: `sendCode(email:)`, `verify(email:code:)`, `signOut()`, `syncNow()`.
  - Testable dispatch: `static func perform(_ cmd: SessionCommand, on app: AppState) -> Bool`. It returns true when the command was acted on.

Behaviour:
- **Launch:** if the auth session exists, set `.signedIn`, run `syncNow()` and `startRealtime`, then handle pending commands.
- **`syncNow()`:** push then pull, guarded so passes don't overlap. Set `lastSync` and clear or set `lastError`.
- **Timers:** a 30 s timer runs `syncNow()` while signed in. `AppState` calls `coordinator.syncSoon()` (a 1 s debounce) after a session closes and after each checkpoint.
- **Realtime:** a change event calls `syncSoon()`. A `session_command` insert, or the pending list fetched on launch, goes through these steps for each row:
  1. Delete it unhandled when `now - created_at > 10 s`.
  2. Otherwise run `perform(parse(row))`.
  3. Then `deleteCommand(row.id)`; deleting is the acknowledgement.
  4. If `parse` returned nil, still delete it, and log it.
- **`perform`:**
  - `start` is ignored if a session is running or the project isn't found locally (it returns false and still gets deleted).
  - `takeBreak` and `resume` require a running session.
  - `endEarly(reason)` calls `app.endEarly(reason:)`. The phone already ran the 60 s cooldown (§6.11).
- **AccountView**, shown as a sidebar item "Account":
  - **Signed out:** an email field, then "Send code"; then a code field, then "Verify". Under `#if DEBUG` show the hint "Local dev: the code is in Inbucket at http://127.0.0.1:54324".
  - **Signed in:** the email, "Last synced 2 min ago" (or the error, in `Theme.warn`), "Sync now", a "Name friends see" field bound to `@AppStorage("displayName")`, and "Sign out".
  - Changing the display name or the break allowance marks the profile dirty by bumping `UserDefaults` `profileUpdatedAt = now`. The profile push sends `updated_at = profileUpdatedAt`.
- **Config:** read `StintSupabaseURL` and `StintSupabaseAnonKey` from `Bundle.main`. If either is missing, the coordinator stays `.signedOut` and AccountView shows "Sync not configured".
- **`project.yml`:** add the Info keys `StintSupabaseURL: $(STINT_SUPABASE_URL)` and `StintSupabaseAnonKey: $(STINT_SUPABASE_ANON_KEY)`, with base settings defaulting to the local stack values from `supabase status`. Add `NSAppTransportSecurity: {NSAllowsLocalNetworking: true}`.
